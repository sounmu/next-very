# 마진로그 MVP - 메뉴 원가 개선

기준: Figma `마진로그` 파일의 섹션 "MVP 와이어프레임 · 메뉴 원가 개선" (node 39:353). 보드 이미지는 `design/figma/wireframe-39-353.png`에 있다. 단, 04 화면은 와이어프레임의 "원가 개선 시뮬레이션"을 "구매처 등록"으로 바꿨다(아래 "와이어프레임과 다른 점").

## 한 줄 정의

사장님이 어떤 메뉴의 원가가 왜 올랐는지 확인하고, 더 싼 구매처를 등록한 뒤 그 구매처의 명세서로 원가가 실제로 내려갔는지 확인하는 앱.

## 피봇: 무엇이 바뀌었나

| 구분 | 이전 (`design/` 목업 14개) | 지금 (이 문서) |
|---|---|---|
| 출발점 | 홈 대시보드의 순수익 | 메뉴 목록의 1인분 원가 |
| 핵심 질문 | 이번 달 얼마 남았나 | 어떤 메뉴 원가가 왜 올랐나 |
| 가격 비교 | 익명 동네 매장 중앙값 | 내 매입 이력 + 공공 시세(KAMIS) 참고 |
| 구매처 | 앱이 추천하고 연결 요청 | 사장님이 직접 알아본 구매처와 받은 단가를 등록 |
| 결과 | 절감 가능액 | 새 구매처 명세서로 실제 원가 갱신 |

이번에 제외: 통합 손익, 순수익 그래프, 매출 입력, 익명 동네 평균, 앱이 하는 구매처 추천·중개·자동 주문, 전 메뉴 자동 레시피, 근거 없는 월/연 절감액. `design/`의 기존 화면은 시각 스타일(색, 글꼴, 카드) 참고용으로만 남긴다.

## 와이어프레임과 다른 점

- 04: 가정 단가를 넣어 보는 시뮬레이션 대신, 실제 구매처(이름, 연락처, 받은 단가, 조건)를 등록한다. 등록한 구매처와 단가는 저장된다.
- 03의 버튼 문구: "구매단가를 바꿔 계산하기" -> "다른 구매처 등록하기".
- 05~07의 시연 명세서는 새로 등록한 구매처(한우리축산)에서 온다. 06에서 등록한 견적과 실제 명세서 단가를 맞춰 본다.

## 지킬 기준

1. 메뉴 원가는 확인한 매입가로만 계산한다. 원가 = 확인한 매입단가 x 레시피 사용량.
2. 구매처에서 받은 단가는 "견적"이다. 견적은 저장하지만 메뉴 원가를 바꾸지 않는다. 그 구매처의 명세서를 확인해야 원가가 바뀐다.
3. 공공 시세는 점검 신호로만 쓴다. 구매 가능 가격이 아니며 매입단가를 덮어쓰지 않는다.
4. 레시피와 사용량을 AI가 추정해 사실처럼 넣지 않는다. 사장님이 처음 한 번 입력한다.
5. 판매량 데이터가 없으므로 월/연 절감액을 보여 주지 않는다. "한 그릇당" 변화만 말한다.

## 시연 흐름

```
01 메뉴 목록 -> 02 메뉴 원가 상세 -> 03 재료 가격 추세 -> 04 구매처 등록
  -> (새 구매처에서 매입) 05 거래명세서 등록 -> 06 추출 결과 확인 -> 07 메뉴 원가 갱신

처음 쓰는 사장님: 08 메뉴·레시피 등록 (01의 "메뉴·레시피 등록 / 수정"에서 진입) -> 01
```

시연은 레시피가 이미 등록된 상태(서버 시드 데이터)로 01에서 시작한다. 08은 01 버튼으로 보여 준다. 04에서 05로 넘어갈 때 발표자가 "다음 날 한우리축산에서 고기가 왔다"고 말로 잇는다.

## 화면 명세

하단 고지 문구: 01~03은 "식재료 원가 기준 · 인건비 등 제외", 04는 "견적 단가 · 명세서 확인 전에는 원가에 반영되지 않음", 07은 "갱신된 식재료 원가 · 실제 순이익 아님".

### 01 메뉴 목록 (출발점)

- 제목 "우리 가게 메뉴", 부제 "최근 매입가격을 반영한 1인분 원가".
- 알림 카드(강조): 원가가 오른 메뉴가 있으면 맨 위에 하나 띄운다. "제육덮밥 원가가 200원 올랐어요 / 돼지고기 매입가격이 달라졌어요." 버튼 [오른 이유 보기] -> 02.
- 메뉴 카드: 이름, 판매가, 식재료 원가, 원가율. 변화가 있으면 "이전 대비 +200원".
- 04에서 구매처를 등록한 뒤에는 해당 메뉴 카드에 "새 구매처 견적 등록됨 · 매입 전" 표시를 붙인다.
- 정렬: 가격 변화가 있는 메뉴 먼저.
- 하단: [메뉴·레시피 등록 / 수정] -> 08, [새 거래명세서 등록] -> 05.

### 02 메뉴 원가 상세 (원인 재료 찾기)

- 큰 숫자 현재 식재료 원가 3,200원, "이전 3,000원 대비 +200원", 원가율 "30% -> 32%".
- 재료별 원가 구성: 변화가 있는 재료는 단독 카드(돼지고기 앞다리 · 국산 냉장, 200g / 10,000원·kg, 1인분 2,000원, 이전 1,800원 대비 +200원, 구매처 대성유통), 나머지는 한 카드에 행으로.
- 결론 한 줄: "원가 상승 200원은 모두 돼지고기에서 발생".
- 버튼 [원인 재료 자세히 보기] -> 03.

### 03 재료 가격 추세 (내 이력과 시장 참고를 구분)

- 내 실제 매입가 카드: 10,000원/kg, 이전 매입가 9,000원, 최근 변화 +11.1%, "근거: 10/28 대성유통 거래명세서".
- 추세 카드: 최근 4주, 각 계열 첫 주 = 100으로 정규화. 내 매입가 지수 100 -> 111, 시장 참고 지수 100 -> 97. 선 2개 그래프.
- 출처 문구: "KAMIS 소매가 · 품목·등급·지역 확인". 시연 수치가 예시면 예시라고 표시한다.
- 안내 카드 "다음 발주 전에 확인해 보세요": 내 가격은 올랐지만 시세는 내렸으니 기존 거래처에 단가를 묻거나 다른 구매처에 견적을 받아 보라고 권한다.
- 주의 문구: 소매 시세는 납품 견적이 아니다.
- 대응 시세가 없는 재료(예: 제육 소스)는 "참고 시세 없음"을 보이고 내 이력만 그린다.
- 등록된 구매처 목록(현재 대성유통)과 각 구매처의 최근 단가를 작게 보여 준다.
- 버튼 [다른 구매처 등록하기] -> 04.

### 04 구매처 등록 (실제 구매처와 받은 단가 입력)

- 제목 "다른 구매처 등록", 재료 "돼지고기 앞다리 · 국산 냉장".
- 현재 구매처 카드: 대성유통, 10,000원/kg, 10/28 매입.
- 입력 폼:
  - 구매처 이름 (필수): 한우리축산
  - 연락처 (선택): 010-0000-0000 형식, 시연값은 가짜 번호
  - 받은 단가 (필수): 9,000원/kg
  - 규격 (필수): 10kg 박스
  - 조건 메모 (선택): 최소주문, 배송비, 배송일. 시연값 "최소주문 10kg · 배송비 없음 · 익일배송"
- 입력하는 동안 보이는 비교 카드: "이 단가로 사면 제육덮밥 3,200 -> 3,000원, 원가율 32% -> 30%, 한 그릇당 200원 감소", 근거 "사용량 200g x kg당 1,000원 차이". 이 재료를 쓰는 메뉴가 여러 개면 메뉴마다 한 줄.
- 확인할 것 카드: 같은 규격·등급인지, 배송비·최소주문·품질 조건.
- 버튼 [구매처 저장] -> 저장 완료 상태로 바뀌고 [이 구매처 명세서 등록하기] -> 05.
- 저장되는 것: 구매처(이름, 연락처, 메모)와 견적(재료, 단가, 규격, 날짜). 메뉴 원가는 그대로다.

### 05 거래명세서 등록 (새 구매가격 입력 수단)

- 사진 영역 + [사진 촬영], [앨범에서 선택].
- 시연할 명세서 카드: 한우리축산 · 11/04, 돼지고기 앞다리 10kg x 1, 합계 90,000원.
- 버튼 [이 사진에서 품목 읽기] -> 06. 추출 중 상태를 보여 준다(서버 OCR, 2~6초).
- 주의: 결제 총액만 있는 사진은 단가 분석이 어렵다.

### 06 추출 결과 확인 (반영 전 검증)

- "1개 품목 추출 · 확인 필요", [원본 사진 보기].
- 구매처 카드: 한우리축산, 거래일 11/04. 등록된 구매처와 이름이 맞으면 "등록한 구매처" 표시. 처음 보는 구매처면 이 화면에서 새 구매처로 만든다.
- 품목 카드(편집 가능): 규격 10kg/박스, 구매 수량 1박스, 구매 금액 90,000원, 환산 매입가 9,000원/kg. 환산 = 금액 / (수량 x 포장 중량).
- 견적 대조: "04에서 등록한 견적 9,000원/kg과 같아요." 다르면 차이를 보여 준다.
- 연결할 재료: 돼지고기 앞다리 · 국산 냉장, 제육덮밥 레시피에 연결, 이전 -> 새 매입가 10,000 -> 9,000원.
- 신뢰도가 낮은 칸(규격 미상, 수량 x 단가 != 금액)은 강조하고, 사용자가 고치기 전에는 확인 버튼을 막는다.
- 버튼 [확인하고 메뉴 원가 갱신] -> 07. 누르면 매입 기록을 confirmed로 저장한다.
- 품목명이나 규격이 불명확하면 재료에 자동 연결하지 않는다. 확인 전 품목은 원가 계산에서 뺀다.

### 07 메뉴 원가 갱신 (결과)

- "메뉴 원가가 갱신됐어요", "11/04 한우리축산 매입 · 확인 후 반영".
- 제육덮밥 3,000원/1인분, 직전 대비 -200원, 원가율 32% -> 30%, "돼지고기 매입가 10,000 -> 9,000원/kg · 대성유통 -> 한우리축산".
- 갱신된 메뉴 목록: 제육덮밥 3,000원 · 30%, 김치찌개 2,700원 · 30%, 계란말이 2,000원 · 25%.
- 이번에 확인된 것: 새 매입가가 레시피에 반영됨. 판매량·재고·배송비를 합한 실제 절감액은 계산하지 않았다고 밝힌다.
- 버튼 [반영한 명세서 보기], [새 거래명세서 등록] -> 05. 01로 돌아가면 알림 카드가 사라지고 숫자가 바뀌어 있어야 한다.

### 08 메뉴·레시피 등록 (최초 설정)

- 기본 정보: 메뉴명, 판매가, 기준 인분(1인분).
- 재료별 사용량(구매 중량 기준): 재료명 + g. [재료 추가].
- 안내: 처음 한 번 사용량을 확인하면 이후에는 명세서로 구매가격을 갱신한다.
- 버튼 [저장하고 메뉴 목록 보기] -> 01.
- 매입가가 없는 재료가 하나라도 있으면 그 메뉴는 전체 원가를 표시하지 않고 "매입가 미등록 재료 n개"를 보인다.

## 예외 상태

| 상황 | 처리 |
|---|---|
| 매입 이력이 1건뿐 | 현재 원가만 표시, 이전 대비 숨김 |
| 공공 시세 미지원 품목 | "참고 시세 없음", 내 구매 이력만 표시 |
| 규격 미상 / 품목 불명확 | 확인 전 갱신 보류, 자동 연결 안 함 |
| 수량 x 단가와 금액이 다름 | 해당 행 강조, 확인 전 갱신 보류 |
| 명세서 단가가 견적과 다름 | 차이를 보여 주고 명세서 단가로 반영 |
| 명세서 구매처가 미등록 | 06에서 새 구매처로 등록 |
| 레시피 재료 중 매입가 없음 | 메뉴 전체 원가를 표시하지 않음 |
| 결제 총액만 있는 사진 | 단가 분석 불가 안내 |
| OCR 실패나 시간 초과 | 서버가 시연용 고정 추출 결과를 돌려주고 06에 "데모 데이터" 표시 |

## 시연 데이터

모든 화면은 아래 숫자만 쓴다. 숫자를 바꾸면 이 표부터 고친다. 김치찌개와 계란말이의 재료 구성은 와이어프레임에 없어서 합계가 맞도록 정한 시연값이다.

매장: 한끼식당. 금액 단위 원, 매입단가 단위 원/kg.

### 구매처

| 구매처 | 상태 | 비고 |
|---|---|---|
| 대성유통 | 시드 | 기존 거래처. 모든 재료의 10월 매입 |
| 한우리축산 | 04에서 시연 중 등록 | 돼지고기 앞다리 견적 9,000원/kg, 10kg 박스, 최소주문 10kg · 배송비 없음 · 익일배송 |

### 재료와 확인된 매입가

| 재료 | 매입가 (확인됨) | 공공 시세 |
|---|---|---|
| 돼지고기 앞다리 · 국산 냉장 | 9,000 (10/07 대성유통) -> 10,000 (10/28 대성유통) | 지원 |
| 쌀 | 3,000 | 지원 |
| 양파 | 3,000 | 지원 |
| 대파 | 5,000 | 지원 |
| 제육 소스 | 13,000 | 미지원 |
| 김치 | 6,000 | 미지원 |
| 돼지고기 목살 | 13,000 | 지원 |
| 두부 | 4,000 | 미지원 |
| 계란 | 9,000 | 지원 |
| 당근 | 4,000 | 지원 |
| 식용유 | 7,000 | 미지원 |

돼지고기 앞다리 외 재료는 10/07 대성유통 매입 1건씩만 있어서 "이전 대비"가 생기지 않는다.

시연 중 추가되는 매입: 11/04 한우리축산, 돼지고기 앞다리 10kg x 1, 90,000원 -> 9,000원/kg.

### 메뉴와 레시피 (1인분)

| 메뉴 | 판매가 | 레시피 (g, 괄호는 재료비) | 원가 / 원가율 |
|---|---|---|---|
| 제육덮밥 | 10,000 | 돼지고기 앞다리 200 (2,000), 쌀 100 (300), 양파 50 (150), 대파 20 (100), 제육 소스 50 (650) | 10/28 이전 3,000 / 30%, 10/28 후 3,200 / 32%, 11/04 후 3,000 / 30% |
| 김치찌개 | 9,000 | 김치 150 (900), 돼지고기 목살 70 (910), 두부 100 (400), 쌀 100 (300), 대파 20 (100), 양파 30 (90) | 2,700 / 30% |
| 계란말이 | 8,000 | 계란 180 (1,620), 당근 30 (120), 대파 20 (100), 양파 30 (90), 식용유 10 (70) | 2,000 / 25% |
