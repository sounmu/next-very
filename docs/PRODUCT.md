# 마진로그 v2 제품 명세

시각 규칙은 `DESIGN.md`(포인트 색 딥 블루 #1E4E8C)를 따른다. 기술 계약은 `docs/TECH.md`에 있다. 이 문서의 숫자와 문구가 앱 화면의 기준이다. 숫자를 바꾸면 이 문서부터 고친다.

## 한 줄 정의

마진로그는 작은 음식점과 카페 사장님이 영수증과 주문내역 사진으로 구매를 기록하면, 그 기록으로 재료 단가와 메뉴별 식재료비를 계산하고 더 나은 구매 조건을 찾아 주는 앱이다.

핵심 가치: **구매 기록을 원가 데이터로, 원가 데이터를 더 나은 구매로.**

- 사장님은 사진을 찍고 확인만 한다. 품목, 용량, 수량, 금액은 AI가 읽고 사장님이 고친다.
- 메뉴 원가는 확인된 구매 기록으로만 계산한다. 추정한 숫자를 원가처럼 보여 주지 않는다.
- 비교는 같은 단위와 같은 규격끼리만 한다. 배송비와 최소 주문 금액까지 넣은 합계로 추천한다.

## 사용자 흐름

| 단계 | 하는 일 | 결과 |
|---|---|---|
| 1. 기록 | 영수증이나 주문내역 사진을 올린다. AI가 날짜, 구매처, 품목, 포장 용량, 수량, 금액을 읽는다. 사장님이 확인하고 고친 뒤 저장한다. | 확인된 구매 기록 |
| 2. 원가 | 포장 용량을 기본 단위(g, mL, 개)로 바꿔 단가를 구한다. 먼저 산 재고부터 쓴다고 보고(선입선출), 지금 쓰는 재고의 단가에 레시피 사용량을 곱해 메뉴 식재료비와 원가율을 낸다. 판매한 만큼 재고가 줄고, 쓰던 재고를 다 쓰면 다음 재고의 단가로 바뀐다. | 재료 재고와 단가, 메뉴 원가, 원가율, 메뉴별 판매 수 |
| 3. 비교 | 내 단가의 변화와 공급처 상품의 조건(규격, 등급, 단가, 배송비, 최소 주문)을 본다. | 같은 조건 상품 중 합계가 가장 싼 추천 |
| 4. 구매 | 장바구니에 담고 데모 주문을 넣는다. 입고를 확인하면 구매 기록이 생긴다. | 새 구매 기록, 다음 원가 계산에 반영 |

4단계에서 생긴 구매 기록은 재고로 쌓였다가, 그 앞의 재고를 다 쓴 뒤 2단계의 원가 계산에 들어간다. 싸게 산 재고가 들어와도 지금 쓰는 재고가 남아 있는 동안은 원가가 내려가지 않는다.

1단계의 세부 규칙:

- 같은 재료를 다르게 적은 이름(예: "돈앞다리", "돼지 전지")은 별칭으로 한 재료에 묶는다. 사장님이 인식 확인 화면에서 별칭을 추가할 수 있다.
- AI가 확신하지 못한 칸은 "확인 필요"로 표시한다. 사장님이 그 칸을 확인하거나 고치기 전에는 저장할 수 없다.
- 결제 총액만 있고 품목과 수량이 없는 사진은 상세 영수증이나 주문내역을 다시 요청한다. 읽지 못한 정보를 지어내지 않는다.

## 탭 구조와 화면

하단 탭은 정확히 네 개다: **홈 / 기록 / 비교 / 구매**. 순서는 쓰는 빈도 순이다. 식재료와 메뉴 원가, 레시피는 홈에서 들어가는 하위 화면이다. 다섯 번째 탭을 만들지 않는다.

사장님은 루프 순서대로 앱을 쓰지 않는다(납품 직후에는 기록만, 값이 올랐을 때만 비교). 그래서 루프는 탭 순서로 보이지 않고 두 가지로 보인다:

- 홈의 "지금 할 일": 루프에서 사장님이 막힌 곳만 한 줄씩 보인다. 없으면 섹션을 숨긴다.
- 화면 끝의 다음 단계 버튼 하나: 기록 저장 -> "메뉴 원가 보기", 메뉴 원가 상승 -> "{재료} 더 싸게 사는 곳 보기", 비교 추천 -> "장바구니 담기", 입고 확인 -> "메뉴 원가 보기".

화면마다 큰 숫자는 하나, 주요 버튼은 하나다. 산출 기준 같은 안내 문구는 화면 맨 아래 작은 글씨 한 줄로 모은다.

| 탭 | 화면 | 들어가는 곳 |
|---|---|---|
| 홈 | 홈 대시보드 | 탭 |
| 홈 | 마이페이지(가게 정보, 계정, 로그아웃) | 홈 헤더 우측 사람 아이콘 |
| 홈 | 식재료 목록, 식재료 상세(단위, 최근 단가, 이력) | 홈 "재료별 구매 단가" |
| 홈 | 메뉴 원가 상세, 레시피 편집 | 홈 "메뉴별 식재료비"의 메뉴, 메뉴 추가 |
| 기록 | 구매 기록(업로드, 검색, 목록) | 탭 |
| 기록 | 인식 결과 확인 | 사진 업로드 직후 (확인 대기 목록은 없다) |
| 기록 | 구매 기록 수정 | 목록의 기록 |
| 비교 | 공급처 비교와 추천 | 탭, 홈의 "지금 할 일", 메뉴 원가 상세의 다음 단계 버튼 |
| 구매 | 공급처 상품, 장바구니 | 탭, 비교의 "장바구니 담기" |
| 구매 | 주문 확인, 주문 상세와 입고 확인 | 장바구니, 구매 탭의 "입고 확인", 홈의 "지금 할 일" |

## 로그인과 가게 설정 (1단계: 화면만)

1단계는 화면과 흐름만 만든다. 인증 서버와 가게별 서버 데이터는 2단계에서 붙인다.

- 첫 화면은 로그인이다. 로그인·회원가입·가게 설정 화면에서는 하단 탭을 숨긴다.
- 로그인: 서비스명 "마진로그", "우리 가게 원가 관리, 여기서 시작하세요.", 이메일, 비밀번호(표시·숨기기), "로그인", "처음이신가요? 회원가입". 아래에 "데모로 시작하기"와 "시연 가게 둘러보기".
- 회원가입: "마진로그 시작하기", 이메일, 비밀번호(8자 이상, 영문과 숫자), 비밀번호 확인, "회원가입", "이미 계정이 있으신가요? 로그인", "데모로 시작하기".
- 형식이 맞아도 로그인·회원가입은 되지 않는다. 입력란 아래에 "아직 로그인(회원가입) 서버에 연결되지 않았어요"를 보이고, 계정이 만들어진 것처럼 안내하지 않는다. 비밀번호는 어디에도 저장하지 않는다.
- "데모로 시작하기": 이 기기에 새 가게를 만든다. 가게 설정을 마쳤으면 바로 홈, 아니면 가게 정보 입력으로 간다.
- "시연 가게 둘러보기": 한끼식당 서버 데이터(재고, 정산, 원가 시연)로 들어간다. 마이페이지의 "로그아웃"으로 로그인 화면에 돌아온다.
- 가게 정보 입력("어떤 가게를 운영하시나요?"): 가게 이름(필수), 지역(시·도와 시·군·구, 기본 "서울특별시 / 성북구"), 업종 카드 셋 중 하나(파스타, 카페, 분식. 선택한 카드는 파란 테두리와 면, 체크). 둘 다 정하기 전에는 "우리 가게 시작하기"가 비활성이다.
- 시작하면 가게 정보와 업종별 예시 메뉴 3개(1인분)를 저장하고 홈으로 간다. 예시 메뉴는 `packages/core/src/store.ts`의 고정 데이터이고, 설정할 때 한 번만 넣는다(연속 클릭, 재진입, 새로고침에도 다시 넣지 않는다). 저장에 실패하면 입력을 그대로 두고 "다시 시도"를 보인다.
- 새 가게 홈: 가게 이름과 지역·업종, 한 번만 보이는 "가게 설정이 완료됐어요 · 선택한 업종의 기본 레시피 3개를 준비했어요.", "우리 가게 메뉴"(메뉴명, "예시 레시피" 배지, 1인분 기준, "원가 계산 전"). 새 가게는 자기 메뉴만 보이고 한끼식당 데이터는 보이지 않는다. 기록·비교·구매 탭은 "서버 연결 뒤에" 안내만 보인다.
- 메뉴 상세: 재료, 사용량, 단위, 재료마다 "단가 미등록", 식재료비 "계산 전". "레시피 수정"으로 재료 이름, 사용량, 단위를 고치고 재료를 더하거나 뺀다. 저장하면 "예시 레시피" 배지가 사라지고, 예시 데이터로 다시 덮어쓰지 않는다.
- 단가는 지어내지 않는다. 0원 대신 "단가 미등록"과 "계산 전"을 쓴다.
- 새 가게 데모 재고: 가게 설정 때 레시피 재료마다 예시 처음 재고를 한 번 넣고 "데모 재고"로 표시한다(`packages/core/src/storeStock.ts`). 같은 이름의 재료는 메뉴끼리 재고 하나를 같이 쓴다. 물은 재고로 관리하지 않는다. 카페 예시: 원두 1kg, 우유 5L, 바닐라시럽 100mL.
- 홈 "우리 가게 메뉴"의 줄마다 메뉴명, "오늘 N잔(인분) 판매", "판매 +1". 누르면 레시피 사용량만큼 재고에서 빼고 "카페라테 1잔 기록했어요 · 실행 취소"를 5초 보인다. 실행 취소는 판매 수와 뺀 재고를 그대로 되돌린다. 매출과 수익은 계산하지 않는다.
- 홈 "재료 재고": 재료마다 남은 양("원두 982g", "우유 4.8L")과 처음 양. 0이면 "재고 없음".
- 재고가 모자라면 판매를 기록하지 않고 재고도 빼지 않는다. "우유가 부족해요"처럼 모자란 재료를 알린다. 재고는 음수가 되지 않는다. 레시피에 재고 없는 재료나 단위가 다른 재료가 있으면 그 이름을 알리고 판매하지 않는다.
- 재고와 판매 기록은 이 기기에 남아 새로고침, 로그아웃 뒤에도 유지된다. 처음 재고는 재료마다 한 번만 넣는다. 입고, 폐기, 실사 정정, 변동 이력, 알림, 구매 연결은 이번 범위에 없다.
- 마이페이지: 두 홈(새 가게, 시연 가게) 헤더 우측의 사람 아이콘 버튼으로 연다. 하단 탭 없이 "← 홈"으로 돌아간다. 가게(새 가게는 이름·지역·업종·등록된 메뉴 수, 시연 가게는 "한끼식당 · 시연 가게"), 계정("이 기기에서만 사용 중" 또는 "시연 가게 둘러보는 중", "계정 로그인은 아직 서버에 연결되지 않았어요."), "로그아웃". 로그아웃은 "로그아웃할까요?"로 한 번 확인하고 로그인 화면으로 간다. 새 가게는 로그아웃해도 이 기기에 가게 정보, 메뉴, 재고, 판매 기록이 남고 "데모로 시작하기"로 이어서 쓴다.

## 화면별 내용

모든 화면에 공통으로 적용하는 상태:

| 상태 | 표시 |
|---|---|
| 로딩 | 고정 크기 스켈레톤. AI 인식 중에는 "구매 내역을 읽고 있어요" |
| 빈 상태 | 가짜 숫자 없이 다음 행동 하나를 안내 |
| 오류 | 이미 받은 데이터는 그대로 두고, 갱신 실패와 재시도 버튼을 보인다. 저장 실패 때 입력값을 지우지 않는다 |
| 확인 필요 | 문제가 있는 칸만 경고 면(state.warningBg)과 "확인 필요" 문구로 표시 |

### 홈 대시보드

위에서 아래 순서:

1. 헤더 "우리 가게 원가".
2. 대표 카드(노랑, 화면에 하나): 원가가 오른 메뉴가 있으면 그 메뉴, 없으면 첫 메뉴. 시드 상태에서는 "제육덮밥 · 1인분 식재료비 / 3,200원 / 원가율 32% · 이전보다 200원 높음 / 돼지고기 앞다리 구매 단가가 올랐어요"와 버튼 "원가 보기"(메뉴 원가 상세).
3. 영업 정산 카드: 버튼 "{날짜} 정산하기"(시드 상태에서 "10월 31일 정산하기"). 누르면 그날 판매를 기록하고 결과를 보인다: "10월 31일 판매 · 카페라테 5개 · 계란말이 7개 · 제육덮밥 6개 · 김치찌개 7개", 원가가 바뀐 메뉴("제육덮밥 원가 3,200원 → 3,000원") 또는 "메뉴 원가는 그대로예요 · 쓰던 재고가 아직 남아 있어요". 재료가 모자라 목표만큼 못 만든 메뉴는 "재고 부족: 김치찌개". 버튼은 다음 날짜로 바뀐다. 정산 규칙은 "계산 규칙 > 영업 정산(데모)".
4. 지금 할 일: 할 일이 있을 때만 보인다. 한 줄씩:
   - {원가 상승 원인 재료} 더 싸게 사기 (추천 공급처 · 배송비 포함 합계) -> 비교 상세. 시드 상태에서 "돼지고기 앞다리 더 싸게 사기 · 한우리축산 · 배송비 포함 93,000원".
   - 입고 확인 N건 (첫 상품 · 주문 총액) -> 주문 상세.
5. 메뉴별 식재료비: 메뉴 이름, 판매가와 누적 판매 수("누적 92개 판매"), 식재료비, 원가율. 오른쪽 위 "전체 보기".
6. "재료별 구매 단가" 한 줄 -> 식재료 목록.
7. 맨 아래 작은 글씨 "남은 재고의 구매 단가 기준(먼저 산 것부터) · 배송비 제외".

대표 카드는 원가가 오른 메뉴, 없으면 직전보다 원가가 바뀐 메뉴, 그것도 없으면 첫 메뉴다. 내려간 경우 "이전보다 200원 낮음 · 돼지고기 앞다리 새 재고로 바뀌어 내려갔어요".

빈 상태: 구매 기록이 없으면 "첫 구매 기록을 등록해 주세요"와 영수증 등록 버튼. 메뉴가 없으면 "레시피를 등록하면 메뉴별 식재료비를 볼 수 있어요". 재료 단가를 단순히 더해 가게 전체 원가처럼 보여 주지 않는다. 매출과 수익 숫자는 넣지 않는다.

### 식재료 목록과 상세

- 목록 행: 재료 이름, 규격, 최근 단가("100g당 1,000원", "100mL당 280원", "개당 50원"), 단가 기준일.
- 상세: 기본 단위, 별칭 목록, 지금 쓰는 재고 단가와 그 근거("10월 28일 대성유통 구매분 · 재고 1600g 남음"), 재고(구매분마다 "10000g 중 1600g 남음", 단가, "지금 사용" / "대기" / "다 씀"), 구매 이력(날짜, 구매처, 포장 용량 x 수량, 금액, 단가). 재고가 0이면 "재고 없음 · 마지막 구매 단가로 계산해요".
- 상세에서 이름, 규격, 별칭을 고칠 수 있다. 기본 단위는 구매 기록이 있으면 바꾸지 않는다.
- 구매 기록이 없는 재료: "단가 등록 필요".

### 메뉴 원가와 레시피

- 메뉴 원가 상세: 헤더에 누적 판매 수. 큰 숫자로 식재료비, 판매가, 원가율, 직전 대비 변화("이전 3,000원보다 200원 높음"). 재료 행마다 사용량, 적용 단가, 구매처와 구매분 날짜, 그 재고의 남은 양과 다음 재고 단가("이 재고 1600g 남음 · 다음 재고 100g당 900원"), 재료비. 재고가 모자라면 "재고 부족 · 마지막 구매 단가 적용".
- 산출 기준 문구: "남은 재고의 구매 단가 기준(먼저 산 것부터) · 배송비 제외".
- 레시피 편집: 메뉴명, 판매가, 제공 기준(1인분, 1잔), 재료 검색과 선택, 사용량과 단위. 재료 행 예시 "우유 / 250 / mL / 700원". 하단 합계 "1잔 식재료비 1,140원"과 "레시피 저장".
- 단가가 없는 재료: 행에 "단가 등록 필요". 메뉴 합계 자리에 "일부 재료 단가 미등록"과 계산된 부분 합계를 따로 보인다. 부분 합계를 완성된 원가처럼 쓰지 않는다.
- 단위가 맞지 않는 재료(예: g으로 사는 재료를 mL로 입력): 행에 "단위 확인 필요"와 재료의 기본 단위를 보이고, 합계를 계산하지 않는다.
- 메뉴 삭제는 확인을 한 번 받는다.

### 기록: 업로드, 인식 확인, 구매 내역

- 구매 기록 화면: 헤더 "구매 기록". 직접 입력은 영수증 등록 화면의 헤더 버튼으로 들어간다. 영수증 등록은 화면 우측 아래(탭바 위)의 떠 있는 + 버튼으로 연다. 아래에 검색(재료 이름, 별칭, 구매처)과 날짜별 구매 기록 목록. 확인을 기다리는 명세서 목록은 두지 않는다. 기간 필터는 두지 않는다.
- 영수증 등록 화면: 사진 촬영과 앨범에서 선택. 헤더 오른쪽 텍스트 버튼 "직접 입력"을 누르면 직접 입력 화면으로 바뀐다.
- 인식 결과 확인: 사진을 올리면 바로 이 화면이 열린다. 저장하지 않고 나가려 하면(뒤로 가기, 제스처 포함) "저장하지 않고 나갈까요?"를 묻고, 나가면 올린 사진과 인식 결과를 지운다. 기록하려면 사진을 다시 올린다. 원본 썸네일과 확대 보기, 구매처와 구매일, 품목별 편집 카드(품목명, 연결할 재료, 포장 용량과 단위, 수량, 품목 합계 금액, 환산 단가). 품목 추가와 삭제가 된다.
- 인쇄된 품목명이 별칭과 맞으면 재료를 자동으로 연결한다. 맞지 않으면 후보만 보이고 사장님이 고른다. 고르면서 "이 이름을 별칭으로 저장"을 켤 수 있다.
- 구매처 이름이 등록된 구매처와 맞으면 연결한다. 처음 보는 구매처는 이 화면에서 새로 만든다.
- "확인 필요" 칸: 포장 용량이나 단위가 비었을 때, 수량 x 단가가 금액과 다를 때, 품목 합이 총액과 다를 때, 포장 용량이 범위를 벗어날 때, AI가 불확실하다고 답했을 때.
- "확인 후 저장"을 누르면 확인된 구매 기록이 생긴다. 저장 뒤 홈의 재료 단가와 그 재료를 쓰는 메뉴 원가가 바뀐다. 같은 명세서를 두 번 저장할 수 없다.
- 구매 기록 수정: 날짜, 구매처, 재료, 포장 용량과 단위, 수량, 금액을 고치거나 삭제한다. 단위를 재료의 기본 단위와 다른 계열로 바꾸면 저장 전에 "이 재료는 g 단위로 계산해요" 같은 경고를 보인다.

### 비교: 공급처 비교와 추천

- 목록 화면: 헤더 "구매가 비교", 재료 검색, 재료마다 한 줄(재료 이름, 내 단가 / 추천 공급처의 배송비 포함 합계). 추천이 있는 재료를 먼저 둔다. 맨 아래 "같은 단위·규격 상품끼리 배송비 포함 합계로 비교해요".
- 상세 화면: 재료 이름과 규격.
- 가격 추이 카드: 내 구매 단가 이력과 지금 단가. 돼지고기 앞다리는 시장 참고 지수(예시)를 같이 그린다.
- 필요량: 기본값은 그 재료의 최근 구매량(돼지고기 앞다리 10kg, 우유 12L). 사장님이 바꿀 수 있다.
- 공급처 상품 카드: 공급처, 상품명, 규격, 등급, 원산지, 포장 용량, 필요한 포장 수, 상품 금액, 배송비(최소 주문 금액은 배송비 아래 작은 글씨), 배송비 포함 합계, 단가. 상품 금액과 배송비 포함 합계를 따로 적는다.
- 추천 카드(노랑): "추천 · 공급처", 배송비 포함 합계, 필요량 기준, 주요 버튼 "장바구니 담기 · N팩". 담은 뒤에는 "장바구니 보기".
- 비교에서 뺀 상품은 아래에 따로 두고 이유를 적는다: "단위가 달라 비교하지 않았어요", "규격이 달라요(수입 냉동)". 최소 주문 금액에 못 미치는 상품은 비교 목록에 두되 "최소 주문 40,000원 미만"으로 표시하고 추천하지 않는다.
- 비교할 상품이 없으면 내 이력만 보이고 "비교할 판매처 가격이 아직 없어요".

### 구매: 상품, 장바구니, 주문, 입고

- 구매 탭: 헤더 "구매"와 오른쪽 "장바구니 N". 입고를 기다리는 주문이 있으면 맨 위에 "입고 확인 N건" 한 줄. 검색, 재료 필터, 상품 카드(상품명, 규격, 공급처, 포장 가격, 포장 용량 · 단가, 배송비 · 최소 주문, 수량과 "담기"). 원산지나 규격이 다른 상품에는 "대체 상품" 표시. 목록 아래 "주문 내역" 한 줄과 정렬 기준("재료별, 배송비 포함 1포장 합계 낮은 순").
- 장바구니: 상품별 수량(포장 단위, 1 이상 정수), 상품 금액 합, 공급처별 배송비, 총액. 배송비는 주문에 들어간 공급처마다 한 번 붙는다.
- 주문 확인: 버튼 "주문하기". 버튼 아래 "결제하지 않고 공급처에 보내지 않아요".
- 주문 상세: 상태(주문함, 입고 완료), 줄별 상품과 금액, 합계. "입고 확인"을 누르면 줄마다 구매 기록이 하나씩 생기고, 다음 행동 "메뉴 원가 보기"가 나온다.
- 완료 화면: 작은 체크 하나, "입고를 확인했어요 · 구매 기록 1건 저장", 다음 행동 "메뉴 원가 보기". 주문 완료와 구매 기록 저장 완료 문구를 구분한다.
- 이미 입고한 주문: "입고 확인" 버튼 대신 "입고 완료 · 10월 31일"을 보인다. 다시 요청해도 구매 기록이 새로 생기지 않는다.

## 계산 규칙

### 단위 체계

| 단위 | 화면 표기 | 기본 단위 | 기본 단위로 바꾸는 배수 |
|---|---|---|---|
| g | g | g | 1 |
| kg | kg | g | 1000 |
| mL | mL | mL | 1 |
| L | L | mL | 1000 |
| ea | 개 | 개 | 1 |

- 재료마다 기본 단위가 하나 있다(g, mL, 개).
- g과 mL은 서로 바꾸지 않는다. 밀도 정보가 없기 때문이다.
- 단가는 기본 단위당 금액이다. 저장과 계산에서 반올림하지 않는다. 화면에서는 g과 mL은 100단위당, 개는 1개당 금액을 정수 원으로 보인다("100g당 1,000원", "100mL당 280원", "개당 50원").

### 메뉴 원가

1. 재고: 재료의 기본 단위와 같은 계열인 확인된 구매 하나가 재고 한 묶음이다(날짜 순, 같은 날이면 id 순). 다른 계열의 구매는 뺀다. 판매 기록의 메뉴 수 x 지금 레시피 사용량만큼, 가장 오래된 묶음부터 뺀다(선입선출).
   - 지금 쓰는 재고: 남은 양이 있는 가장 오래된 묶음. 직전 단가는 그 바로 앞(이미 다 쓴) 묶음의 단가다.
   - 재고가 0이면 마지막 구매 묶음의 단가를 쓰고 "재고 부족"으로 표시한다. 직전 단가는 그 앞 묶음이다.
2. 구매 단가 = 금액 / (포장 용량을 기본 단위로 바꾼 값 x 수량).
3. 재료비 = 반올림(1인분 사용량을 남은 재고에서 오래된 묶음부터 꺼낸 금액). 한 묶음이 중간에 떨어지면 남은 양은 그 묶음 단가로, 모자란 양은 다음 묶음 단가로 계산한다. 재고 전체가 모자란 양은 마지막 구매 단가로 계산한다. 줄마다 정수 원으로 반올림한다.
4. 메뉴 식재료비 = 줄별 재료비의 합. 화면의 줄 합과 합계가 항상 맞는다.
5. 원가율 = 반올림(식재료비 / 판매가 x 100)%.
6. 직전 대비: 적어도 한 재료에 직전 단가가 있을 때만 보인다. 직전 재료비 = 반올림(사용량 x 직전 단가). 직전 단가가 없는 재료는 현재 재료비를 그대로 쓴다.

화면에는 "남은 재고의 구매 단가 기준(먼저 산 것부터)"이라고 적는다. 배송비는 메뉴 식재료비에 넣지 않고 "배송비 제외"라고 적는다.

### 추정하지 않는 경우

| 경우 | 처리 |
|---|---|
| 재료에 확인된 구매 기록이 없음 | 그 줄은 "단가 등록 필요". 메뉴 합계와 원가율은 비우고 부분 합계를 따로 보인다 |
| 레시피 단위가 재료의 기본 단위와 다른 계열 | 그 줄은 "단위 확인 필요". 메뉴 합계와 원가율은 비운다 |
| 구매 기록이 하나뿐 | 현재 단가만 보이고 직전 대비는 숨긴다 |
| 재고가 모자람 | 모자란 양은 마지막 구매 단가로 계산하고 "재고 부족"을 표시한다 |

### 영업 정산 (데모)

실제 판매(POS) 연동은 없다. 시연에서 "정산하기"가 하루 판매를 만든다.

1. 정산 날짜 = 마지막 판매 기록 다음 날. 판매 기록이 없으면 오늘(서울 기준). 시드 상태에서 10월 31일.
2. 메뉴마다(id 순) 목표 판매 수를 3~8개 중에서 뽑는다. 난수는 정산 날짜를 시드로 쓰므로 같은 날짜는 항상 같은 결과가 나온다. 데모 초기화 뒤 같은 순서로 다시 볼 수 있다.
3. 메뉴를 돌아가며 1개씩 만든다. 레시피의 모든 재료가 남은 재고로 1인분 이상 있을 때만 만든다. 목표에 닿거나 재료가 떨어지면 그 메뉴는 멈춘다. 단위가 맞지 않거나 구매한 적 없는 재료가 있는 메뉴는 만들지 않는다.
4. 만든 수만큼 판매 기록(메뉴, 날짜, 수량)을 저장한다. 같은 날짜를 두 번 정산하지 않는다.
5. 매출 금액은 계산하지 않는다. 화면에는 판매 수와 바뀐 메뉴 원가만 보인다.

## 추천 규칙

1. 비교할 수 있는 상품만 비교한다. 상품의 포장 단위가 재료의 기본 단위와 같은 계열이어야 하고, 재료에 규격이 있으면 상품 규격이 같아야 한다. 단위가 다르면 "단위", 규격이 다르면 "규격"을 이유로 뺀다.
2. 필요한 포장 수 = 올림(필요량 / 포장 용량), 최소 1.
3. 상품 금액 = 포장 수 x 포장 가격. 합계 = 상품 금액 + 배송비.
4. 상품 금액이 최소 주문 금액 이상인 상품만 추천할 수 있다.
5. 추천은 그중 합계가 가장 낮은 상품이다. 합계가 같으면 단가가 낮은 상품, 그래도 같으면 id 순.
6. 추천할 상품이 없으면 추천 카드를 보이지 않는다.
7. 목록은 비교할 수 있는 상품을 합계 순으로 먼저, 나머지를 뒤에 둔다.

## 범위 밖

- 결제와 결제 수단 등록.
- 공급처로 주문 전송(전화, 문자, 주문 API 모두).
- 공급처 거래 수수료 정산. 수익 모델은 공급처 거래 수수료지만 이번 범위에서 정산은 만들지 않는다.
- 매출 입력, 순이익, 손익 리포트.
- 실제 로그인·회원가입과 가게별 서버 데이터(2단계에서 붙인다). 새 가게 재고의 입고, 폐기, 실사 정정, 변동 이력, 알림, 구매 연결.
- g과 mL 사이 환산, 배송비를 메뉴 원가에 나눠 넣기.
